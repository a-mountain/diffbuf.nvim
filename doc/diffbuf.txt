INTRODUCTION                                                        *diffbuf*

diffbuf.nvim shows a branch diff in one focused read-only buffer. The base
revision is resolved into a concrete commit when the buffer opens, and that
commit is what the buffer compares against.

By default the commit is the merge base of the repository default branch and
HEAD, which is what a GitHub pull request shows: commits that landed on the
base branch after your branch forked stay out of the diff. Set `merge_base`
to false for a plain two-dot `git diff <base>` comparison instead. Pass an
explicit revision to |:DiffBufOpen| to compare against something else; both
|:DiffBufOpen| completions cover local branches, remote branches and tags.

Requirements: Neovim 0.13+ and Git.

==============================================================================
COMPOSITE BUFFER                                            *diffbuf-composite*

|:DiffBufOpen| renders every changed file in one read-only buffer, hand-written
files first and generated ones last (|diffbuf-generated|). Neovim line numbers
are disabled there; the gutter shows a single working-tree line-number column.
The diff covers committed branch changes plus staged and unstaged changes.

Every file is coloured in the language its path implies, on top of the added
and removed backgrounds. Tree-sitter does it where a parser and its highlights
query are installed; everything else falls back to Vim's own syntax engine,
which covers the configuration, shell and markup files a repository holds and
a review still has to read. Only what a window can see is highlighted, so a
diff of hundreds of files costs nothing until you scroll into it.

Each file's body is parsed on its own and still holds the removed lines, so a
construct that opens outside the shown context can be coloured wrongly;
block-structured formats such as Markdown suffer from this most. `syntax =
false` keeps the whole buffer plain.

A diff meets file types an editing session never opens, and Neovim names the
filetype from the path alone here, without the file's contents. Teach it the
ones your repository uses with `filetypes`, which takes |vim.filetype.add()|
form:
>lua
    require("diffbuf").setup({
      filetypes = {
        extension = { axl = "bzl" },
        filename = { [".bazelrc"] = "conf" },
        pattern = { [".*%.bazel%.lock"] = "json" },
      },
    })
<
The rules go to |vim.filetype.add()| itself, so they apply to the real files
too, not only to their diffs.

The buffer folds itself: each file is a fold and each of its hunks a fold
inside it, so `zc` collapses the hunk under the cursor, a second `zc` its
whole file, and |zM| and |zR| collapse and expand everything. The gutter marks
a fold start with `▾` when it is open and `▸` when it is closed, and a closed
fold reports its hunk header or file name with its line and change counts.

The fold options are window-local and given back when the window shows
another buffer, so a 'foldmethod' or 'foldexpr' of your own is untouched.
'foldlevel' is yours after the buffer is first shown; leaving and re-entering
the buffer starts over from the fully expanded state, with generated files
collapsed again.

==============================================================================
GENERATED FILES                                          *diffbuf-generated*

Lock files, code generator output and snapshots make a diff long without
making it interesting. Both forges mark them in `.gitattributes`, GitHub with
`linguist-generated` and GitLab with `gitlab-generated`:
>text
    *.lock            gitlab-generated=true
    gen/**/*.go       linguist-generated
    src/hand.go       linguist-generated=false
<
diffbuf.nvim reads the same attributes with `git check-attr`, so the files
that arrive collapsed in a merge request arrive collapsed here:

    - the composite buffer moves them behind every hand-written file and
      loads their folds closed, labelled `(generated)`,

Moving them last means the buffer opens on a change worth reading, and `]f`
walks the real work before it reaches the generated tail. Within each group
the order Git reported is kept, so `generated.sort_last` is the only thing
that reorders a diff.

|:DiffBufGenerated| expands and collapses the generated folds inside the
composite buffer; `gh` does the same.

An explicit `=false` or `-linguist-generated` keeps a file out of the set,
which is how a hand-written file inside a generated directory stays visible.
Set `generated.attributes` to `{}` to stop asking Git altogether.

==============================================================================
COMMANDS                                                  *diffbuf-commands*

                                                              *:DiffBufOpen*
:DiffBufOpen [revision]
    Open the composite diff buffer. Without a revision the repository default
    branch is used. Completes revisions.

                                                             *:DiffBufRefresh*
:DiffBufRefresh
    Regenerate the current composite buffer.

                                                           *:DiffBufGenerated*
:DiffBufGenerated
    Collapse or expand the generated files in the composite buffer. See
    |diffbuf-generated|.

==============================================================================
MAPPINGS                                                  *diffbuf-mappings*

diffbuf.nvim sets no global mappings. Map the commands or the Lua API
(|diffbuf-api|) yourself.

Inside a composite buffer:

    gd      Request textDocument/definition for the mapped source location.
    <CR>    Open the mapped working-tree source line.
    ]f/[f   Move to the next/previous changed file.
    ]c/[c   Move to the next/previous hunk.
    gh      Collapse or expand every generated file.
    r       Refresh the diff.
    q       Delete the diff buffer.
    ?       Open this help.

Folds are Neovim's own, so |zc|, |zo|, |za|, |zM| and |zR| all apply; see
|diffbuf-composite|.

For |gd|, diffbuf.nvim lazily loads the real source buffer and waits briefly
for its normal LSP client to attach. Added and context lines map to the
working-tree file. Deleted lines have no working-tree LSP location.

==============================================================================
CONFIGURATION                                              *diffbuf-config*

Setup is optional. Defaults:
>lua
    require("diffbuf").setup({
      context = 3,
      lsp_attach_timeout_ms = 3000,
      syntax = true,
      filetypes = {},
      base = nil,
      merge_base = true,
      generated = {
        attributes = { "linguist-generated", "gitlab-generated" },
        collapse = true,
        sort_last = true,
      },
    })
<
context ~
    Non-negative number of unchanged lines around each hunk in the composite
    buffer.

lsp_attach_timeout_ms ~
    Time to wait for a source buffer's definition provider to attach.

syntax ~
    Highlight the composite buffer per file, with Tree-sitter where a parser
    is installed and Vim's syntax engine everywhere else. See
    |diffbuf-composite|.

filetypes ~
    Filetype rules for paths Neovim cannot name, in |vim.filetype.add()| form
    and handed straight to it. Empty by default.

base ~
    Default base revision. `nil` resolves the repository default branch.

merge_base ~
    Compare against the merge base of the base revision and HEAD, like a
    GitHub pull request. When false, compare against the tip of the base
    revision.

generated.attributes ~
    .gitattributes attributes that mark a file as generated. An empty list
    turns the detection off, and no `git check-attr` runs. See
    |diffbuf-generated|.

generated.collapse ~
    Load generated files with their fold closed in the composite buffer.

generated.sort_last ~
    Lay generated files out after every other file in the composite buffer.
    When false, the buffer keeps the order `git diff` produced.

==============================================================================
LUA API                                                      *diffbuf-api*

>lua
    local diffbuf = require("diffbuf")

    diffbuf.open({ base = "HEAD" })  -- composite buffer
    diffbuf.open({ base = "origin/main", rev = sha })  -- pre-resolved base
    diffbuf.refresh()
    diffbuf.retarget(buf, { ref = "HEAD~1", commit = sha })  -- reload in place
    diffbuf.buffers(root)            -- composite buffers of one repository
    diffbuf.generated_toggle()       -- true once generated folds are collapsed
<
`rev` and |diffbuf.retarget()| let an external review controller own the
base: diffbuf.nvim then compares against the given commit as-is, and the
previous diff stays on screen until the new one is rendered.

==============================================================================
LIMITATIONS                                              *diffbuf-limitations*

- The composite buffer highlights each file's diff body as a standalone
  fragment that still contains the removed lines, so highlighting can be
  wrong where a construct opens outside the context lines. A file Neovim
  cannot name a filetype for stays plain until `filetypes` names it, and a
  file whose diff runs past 5000 lines is left plain rather than parsed.
- Deleted lines in the composite buffer cannot issue LSP requests.
- The composite buffer shows tracked changes only, because untracked files
  are not part of an ordinary `git diff`.
- A source buffer's first LSP request can wait for its configured server to
  attach. diffbuf.nvim does not configure or start language servers itself.
